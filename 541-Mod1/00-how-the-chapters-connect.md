## The requirements hierarchy

This is the backbone of the material:

```
Business requirement
        ↓
User requirement
        ↓
Functional requirement
        ↓
Design
        ↓
Code
        ↓
Tests
```

## Quick recall checklist

- 4 requirement levels: business, user, functional, nonfunctional
- 4 development activities: elicitation, analysis, specification, validation
- 2 halves of requirements engineering: development + management
- 7 traits of a good requirement: complete, correct, feasible, necessary, prioritized, unambiguous, verifiable
- Baseline = snapshot of agreed requirements, not a freeze
- Vision = destination, scope = this trip
- Traceability: requirement → design → code → test
- BA is a role, not a job title: Customer/User ↔ BA ↔ Developer
- 3 analyst backgrounds: former user, former developer, subject matter expert
